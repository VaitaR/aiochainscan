# Аудит кодовой базы aiochainscan
**Дата:** 2026-02-23
**Роль аудита:** Staff/Principal review (Python, high-load systems, data pipelines)

## High-Level Summary
Сильные стороны:
- Есть четкая попытка выстроить hexagonal architecture: `ports`/`adapters`/`services`/`scanners`/`core`.
- Появился единый `ChainscanClient` и расширенный тестовый контур (локально: `333 passed`, `7 skipped`, `12 deselected` при workaround для pytest debugging plugin).
- Есть прогресс по retry/rate-limit abstraction (`tenacity`, `aiolimiter`) и унификация paging-движка.

Главные риски:
- Критические runtime-регрессии в упаковке и конфигурации (`import` в чистом окружении, network alias normalization).
- Архитектурный разрыв: `BlockScout`-сканеры обходят общий транспортный слой и теряют retry/rate-limit/timeout/connection pooling.
- Риски утечки секретов в логах и несогласованные интерфейсные контракты.
- Серьезный техдолг по DRY/типизации/размеру модулей, влияющий на масштабирование и скорость изменений.

### 1)
**Файл / Функция:** `aiochainscan/adapters/__init__.py`, `aiochainscan/adapters/aiohttp_client.py`, `pyproject.toml`

**Проблема:** Пакет импортирует `AiohttpClient` безусловно, но `aiohttp` не объявлен в mandatory dependencies. В «чистом» окружении импорт библиотеки падает (`ModuleNotFoundError: No module named 'aiohttp'`).

### 3)
**Файл / Функция:** `aiochainscan/scanners/blockscout_v1.py:124-169`, `aiochainscan/scanners/blockscout_v2.py:305-352`, `aiochainscan/scanners/blockscout_v2.py:417-444`

**Проблема:** BlockScout-сканеры создают `aiohttp.ClientSession` на каждый вызов и обходят общий `Network` слой (`httpx + retry + aiolimiter`).

**Почему это важно:**
- Потеря connection pooling и рост latency/CPU под нагрузкой.
- Непоследовательная retry/rate-limit политика между провайдерами.
- Неполная обработка ошибок (`raise Exception(...)` вместо доменных исключений).

**Предлагаемое решение:** унифицировать через `Network` (добавить метод запроса arbitrary URL), убрать локальные сессии из сканеров.

```python
# aiochainscan/network.py
async def request(
    self,
    method: str,
    url: str,
    *,
    params: dict[str, Any] | None = None,
    data: dict[str, Any] | None = None,
    headers: dict[str, str] | None = None,
) -> dict[str, Any] | list[Any] | str:
    async def do_request() -> dict[str, Any] | list[Any] | str:
        await self._rate_limiter.acquire('network:request')
        client = await self._ensure_client()
        response = await client.request(method, url, params=params, data=data, headers=headers)
        return self._handle_response(response)
    return await self._retry_policy.run(do_request)
```

```python
# aiochainscan/scanners/blockscout_v2.py (call)
raw_response = await self._network_client.request(
    spec.http_method,
    url,
    params=query_params if spec.http_method == 'GET' else None,
    data=query_params if spec.http_method == 'POST' else None,
    headers=headers,
)
```

### 4)
**Файл / Функция:** `aiochainscan/network.py:172-179`

**Проблема:** В debug-лог пишутся `headers` целиком. При header-auth (`X-API-Key`) ключ утекает в логи.

**Почему это важно:** Утечка секретов в централизованные логи/трейсы — security incident class.

**Предлагаемое решение:** редактировать чувствительные заголовки до логирования.

```python
# aiochainscan/network.py
SENSITIVE_HEADERS = {'authorization', 'x-api-key', 'apikey'}

def _redact_headers(headers: dict[str, str] | None) -> dict[str, str] | None:
    if headers is None:
        return None
    return {
        k: ('***REDACTED***' if k.lower() in SENSITIVE_HEADERS else v)
        for k, v in headers.items()
    }

# при логировании
self._logger.debug(
    '[%s %s] url=%r data=%r headers=%r',
    method,
    response.status_code,
    str(response.url),
    data,
    _redact_headers(headers),
)
```

**Проблема:** Контракт `RateLimiter.acquire(self, key: str)` конфликтует с использованием `await self._rate_limiter.acquire()` без `key`.

await self._rate_limiter.acquire('network:default')

## Архитектурные улучшения и производительность

### 6)
**Файл / Функция:** `aiochainscan/services/paging_engine.py:132-371`

**Проблема:** Полный сбор `all_items` в память с дедупом и сортировкой в конце (`O(N)` memory).

**Почему это важно:** Для «whale» адресов и больших диапазонов это bottleneck и риск OOM.

**Предлагаемое решение:** streaming-first API (yield по мере получения) + внешняя дедуп/сортировка как опция.

```python
async def iter_all_generic(...):
    seen: set[str] = set()
    async for item in _iter_pages(...):
        key = fetch_spec.key_fn(item)
        if key is None or key in seen:
            continue
        seen.add(key)
        yield item
```

### 8)
**Файл / Функция:** `aiochainscan/__init__.py` (2843 строк), `aiochainscan/services/account.py` (1350 строк), `aiochainscan/services/fetch_all.py` (873 строки)

**Проблема:** Очень крупные «god modules», чрезмерный экспорт и высокая связность.

**Почему это важно:**
- Удорожает сопровождение и ревью.
- Увеличивает import-time и риск циклических зависимостей.
- Снижает предсказуемость API surface.

**Предлагаемое решение:** дробление фасада и lazy exports (`__getattr__`), выделение bounded contexts (`facade/account.py`, `facade/logs.py`, ...).

```python
# aiochainscan/__init__.py
def __getattr__(name: str):
    if name in {'get_address_balance', 'get_normal_transactions'}:
        from .facade.account import __dict__ as _acc
        return _acc[name]
    raise AttributeError(name)
```

### 10)
**Файл / Функция:** `aiochainscan/config.py:92-103`, `aiochainscan/config.py:253-281`, `aiochainscan/config.py:578-580`

**Проблема:** На import создается глобальный `config_manager`, который сразу читает `.env`/`config` из `cwd` и мутирует `os.environ`.

**Почему это важно:**
- Непредсказуемые side effects при импорте библиотеки.
- Риск «заражения» окружения в multi-tenant/runtime-сценариях.

**Предлагаемое решение:** lazy initialization и явный вызов загрузки конфигурации.

```python
_config_manager: ConfigurationManager | None = None

def get_config_manager() -> ConfigurationManager:
    global _config_manager
    if _config_manager is None:
        _config_manager = ConfigurationManager(config_dir=Path.cwd())
    return _config_manager
```
